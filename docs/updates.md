# Обновление прошивки

## GitHub

Прошивка проверяет подписанный `releases/stable.json`: после запуска и затем
каждые 6 часов с небольшим случайным сдвигом. Check на странице `/updates`
запускает внеочередную проверку. Нужны доступ в интернет, DNS и корректное NTP-время.

Установка разрешена по умолчанию. Её можно отключить через web или переключатель
«Автообновление» в HA. Запрет любого из них имеет приоритет и сохраняется между
перезагрузками. Check не обходит запрет. После начала управления политикой из HA
требуется её обновление каждые 30 секунд; разрешение истекает через 90 секунд без HA.

Проверяются HTTPS, подпись ECDSA P-256, версия, совместимость профиля, размер и
SHA-256 приложения. Запись выполняется в неактивный слот с последовательным
стиранием секторов. Запуск подтверждается после 45 секунд работы локальных
сервисов. Ранний сбой неподтверждённого приложения позволяет загрузчику откатиться.
Проверка запуска не гарантирует исправность всех прикладных функций.

Новые версии распространяются только через stable-канал. Коммиты, архивы HA и
предварительные релизы сами по себе не запускают обновление. Автоматического
понижения версии нет. Канал `testing.json` предназначен только для испытаний
сопровождающим и не используется обычной публичной прошивкой.

## ArduinoOTA по LAN

Этот способ остаётся доступен отдельно от автоматического обновления. Задайте
индивидуальный пароль в Settings → ArduinoOTA после web-входа. Используйте только
`4vrs-display-<version>.bin` — приложение. **Factory/merged и bootloader нельзя
передавать через OTA.** Wi-Fi, MQTT и web-настройки сохраняются при обычном обновлении.

Ранние приватные сборки могут требовать однократной миграции реквизитов в NVS.
Для них переход согласуется с сопровождающим; публичный factory не заменяет
миграцию настроенного прибора. UART остаётся способом восстановления.

Версии 0.4.0–0.4.2 являются предварительными; стабильный выпуск — 0.4.3.
