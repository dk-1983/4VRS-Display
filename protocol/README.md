# Контракт HA ↔ дисплей: snapshot v1

Первый реализованный обмен, отдельно от будущего полного контракта Apply/медиа/обновлений. Корень topics: `4vrs/display/<device_id>`.

| Суффикс | Отправитель | Содержание |
|---|---|---|
| /request | HA | schema:1, key, request:"hello", request_id (случайные 32 hex) |
| /capabilities | ESP32 | schema, device_id, session, firmware, возможности; ответ hello повторяет request_id |
| /snapshot | HA | Полный снимок по schemas/snapshot-v1.json |
| /ack | ESP32 | schema, session, seq, status accepted/rejected и возможная error |
| /availability | ESP32 | online при подключении, offline через LWT |

QoS 0. Retain только availability. Команды и состояния не сохранять retained. Дисплей отклоняет сообщения с признаком retained-доставки; брокер может убрать этот признак у живой пересылки. ACL брокера должны ограничивать доступ каждого клиента его topics. Ключ в JSON не заменяет TLS и ACL.

Новый сеанс MQTT или новый авторизованный hello создаёт session. Снимки принимаются атомарно только с правильными key/session и возрастающим seq. Повтор hello с тем же request_id не меняет session. В актуальной версии максимум 15360 байт JSON, 1–20 карточек, ttl_s 30–300. Ограничения UTF-8 в байтах дополнительно обозначены x-maxUtf8Bytes в схеме; обычный JSON Schema сам их не проверяет.

HA отправляет снимки при изменениях и каждые 30 секунд, TTL 90. TTL относится к доставке снимка, не к времени физического измерения датчика. При потере связи/истечении TTL последние карточки помечаются устаревшими. При отключении MQTT возвращается встроенная заставка. Данные карточек не сохраняются в NVS.

Поддержаны fan, light, valve, sensor, binary_sensor, switch, text; неизвестные типы HA получают текстовый fallback. unavailable и unknown не равны off. См. examples/snapshot-v1.json; ключи примера вымышленные.

Расширение presentation_v=1: capabilities объявляет поддержку необязательных полей карточки icon (семейство значка из схемы) и alert (boolean). HA добавляет их только после объявления поддержки. Старые сообщения без этих полей принимаются. Классы HA и отображение: [Отображение в HA](../docs/home-assistant.md).

### Помещения
С firmware 0.3.1-areas: capabilities `area_v: 1`, `max_payload: 9216`. Только после согласования обоих полей отправлять необязательный `cards[].area` (строка до 48 байт UTF-8, пустая — без помещения). HA группирует перед отправкой; legacy-пакеты остаются допустимыми. [Правила](../docs/home-assistant.md).

### 20 сущностей и значки комнат
Firmware 0.3.2-room-pages: max_cards=20, max_payload=15360, area_icon_v=1. Необязательная cards[].area_icon из фиксированного enum требует area. HA 0.3.0 отправляет значки только после согласования; сначала обновлять прошивку. Старые пакеты по-прежнему принимаются.
