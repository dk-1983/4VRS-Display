# 4VRS Display

**Маленький дисплей. Большие возможности.**

4VRS Display — открытый проект телеметрического дисплея и самостоятельной фоторамки на ESP32. Температура, влажность, освещение, вентиляция, протечки и другие состояния сущностей отображаются на небольшом экране там, где нужны: в комнате, гараже или серверной.

Вы выбираете сущности в Home Assistant, интеграция передаёт их состояния через MQTT, а дисплей группирует карточки по помещениям. Настройка доступна из браузера, обновление прошивки — по Wi-Fi без снятия установленного прибора.

**Стабильная прошивка: 1.0.0 · Интеграция Home Assistant: 0.4.3 · Лицензия: MIT**

## Возможности

- **До 20 сущностей на дисплей**, с выбором и редактированием в Home Assistant.
- **Показ по помещениям**: полноэкранная заставка с названием и значком, затем страницы максимум по три карточки. Разные помещения не смешиваются на одной странице.
- **Понятные значки и состояния** температуры, влажности, света, вентиляторов, клапанов, датчиков протечки и другого оборудования; для неизвестных типов предусмотрено текстовое отображение.
- **Контроль актуальности данных**: недоступные, неизвестные и устаревшие состояния отличаются от выключенного оборудования.
- **Локальная web-настройка** Wi-Fi, MQTT, языка, реквизитов и обновлений; информация о приборе собрана в разделе About.
- **Английский по умолчанию и русский по выбору** в web-интерфейсе.
- **Фоторамка и GIF-плеер** с загрузкой, предпросмотром, удалением и индивидуальными настройками слайд-шоу через браузер.
- **Резервная встроенная заставка** без карты; демонстрационные изображения пропускаются при наличии пользовательских.
- **Яркость из web и HA**, начальные 50%, тёмный старт и плавное включение после готовности изображения.
- **Смена Wi-Fi с откатом**, статический IPv4 и переименование модуля.
- **ArduinoOTA по локальной сети и подписанные обновления с GitHub**, два раздела приложения, проверка запуска и поддержка отката.
- **Индивидуальная блокировка автообновлений** через web и интеграцию Home Assistant.

Текущий релиз показывает состояния сущностей; управление физическим оборудованием с экрана пока не реализовано.

## Как это работает

```text
Home Assistant → MQTT-брокер → 4VRS Display
Браузер        → локальный web-интерфейс → настройки прибора
Релиз GitHub   → подписанный канал обновлений → обновление прошивки
```

У каждого дисплея собственный идентификатор, ключ сопряжения и список сущностей. Помещение определяется сначала по сущности, затем по её устройству; сущности без помещения образуют отдельную группу.

Например, для комнаты с пятью сущностями показываются заставка и страницы **3 + 2**. Для следующей комнаты с четырьмя сущностями — её заставка и страницы **3 + 1**. Последовательность автоматически повторяется. Заставка комнаты отображается три секунды, страница карточек — восемь секунд. Заставки можно отключить; для единственного помещения они пропускаются автоматически.

Интеграция отправляет снимки данных при изменении состояний и каждые 30 секунд. Через 90 секунд без свежего снимка дисплей помечает данные устаревшими.

## Поддерживаемое оборудование

Текущая прошивка рассчитана на **ESP32-WROVER с 4 MiB PSRAM**, базовую плату **NADIM V5** и **SPI-дисплей ILI9341 240 × 320** в вертикальной ориентации. Это конкретный аппаратный профиль; другие платы ESP32 и дисплеи могут потребовать изменений.

| Сигнал дисплея | GPIO ESP32 |
| --- | --- |
| CS | 13 |
| DC / A0 | 14 |
| RESET | 2 |
| MOSI / SDA | 23 |
| SCK | 18 |
| SDO / MISO, необязательная диагностика | 19 |
| LED / PWM, контакт 8 модуля | 4 |

Дисплей — готовый заводской модуль: на нашей схеме показаны его внешние подключения. GPIO4 соединяется напрямую с контактом 8 (LED), без внешнего транзистора. Уровень сигналов GPIO — 3,3 В; питание модуля подключается согласно его документации. Тачскрин не требуется. SD-карта нужна для пользовательских фото и GIF; без неё доступна встроенная заставка.

### Подключение SD-карты

| Сигнал разъёма SD | GPIO ESP32 |
| --- | --- |
| SD_MOSI / MOSI | 23 |
| SD_MISO / MISO | 19 |
| SD_SCK / CLK | 18 |
| SD_CS / CS | 25 |

Слот карты на модуле дисплея имеет **отдельный разъём**: необходимо распаять все четыре сигнала; внутри модуля они не соединены с разъёмом TFT. Дисплей и SD используют общие MOSI, MISO и SCK, но отдельные CS (TFT: GPIO13, SD: GPIO25). Питание слота поступает через модуль дисплея. Для пользовательских медиа нужна карта FAT32; проверены microSD на 16 ГБ с переходником в полноразмерную SD. Для SD линия MISO обязательна, даже если диагностика TFT не используется.

## Первый запуск

1. Скачайте `4vrs-display-1.0.0-factory.bin` из релиза. Для первоначальной прошивки по UART выберите **ESP32** в утилите Espressif и запишите factory-образ по адресу **0x0**. Он заменяет данные в занимаемой области flash; настроенный прибор обновляйте через OTA.
2. Включите загрузчик платы, запишите образ, дождитесь проверки и выполните обычный RESET без удержания BOOT/PGM.
3. Подключитесь к сети настройки `4vrs-rack-<id>-setup`. Пароль: **`KIaE18TTn4Omp8H-0peXAk1i`**.
4. Откройте **http://192.168.4.1/**, выберите свою сеть **Wi-Fi 2,4 ГГц** и введите её пароль.
5. Найдите выданный прибору IP в списке DHCP-клиентов роутера и откройте его в браузере. Резервирование DHCP позволит сохранить постоянный адрес. После стабильного подключения к локальной сети точка настройки выключается.
6. Войдите с **логином `admin` и паролем `admin`**. Изменить их и выбрать язык можно в **Settings**. Реквизиты web, Wi-Fi и ArduinoOTA независимы.
7. **Для телеметрии Home Assistant:** откройте **MQTT**, укажите адрес брокера без `http://`, порт, пользователя и пароль. Брокер должен быть тем же, который использует Home Assistant.

Без телеметрии используется выбранное медиа, а при отсутствии пользовательских файлов — встроенная заставка. MQTT не обязателен для фоторамки.

## Настройки экрана и сети

- **Настройки → Показывать заставки комнат** включает и отключает экраны названия/значка комнаты. По умолчанию включено; выбор сохраняется после перезапуска и OTA. При отключении название остаётся в заголовке, комнаты не смешиваются.
- **О модуле → Проверить дисплей** читает регистры и поясняет результат. Для обратной связи подключите SDO/MISO к GPIO19. Проверка подтверждает обмен с контроллером, а не исправность матрицы и подсветки.
- **Настройки IPv4**: DHCP по умолчанию либо статический IP, маска, шлюз и два DNS. Для изолированной сети шлюз/DNS можно оставить пустыми; обновления GitHub требуют интернета и DNS. Выбирайте свободный адрес вне динамического пула либо резервируйте его в роутере. Подсеть 192.168.4.0/24 зарезервирована для точки настройки.
- Новая адресация проверяется три минуты. Откройте `/network` по новому LAN-адресу и нажмите **Подтвердить подключение**. Без подтверждения или при отключении питания до подтверждения вернутся прежние настройки. На время проверки доступна точка настройки Wi-Fi, обновления прошивки приостановлены. При первом запуске сначала настройте Wi-Fi.

## Интеграция Home Assistant

В релиз прошивки **1.0.0** входит интеграция Home Assistant **0.4.3**. Компоненты имеют независимые версии; `fourvrs_display-0.4.3.zip` — актуальный архив интеграции для этого релиза.

1. Настройте штатную интеграцию MQTT в Home Assistant.
2. Скачайте `fourvrs_display-0.4.3.zip` из релиза и скопируйте каталог `custom_components/fourvrs_display` в каталог `custom_components` конфигурации HA.
3. Перезапустите Home Assistant и добавьте интеграцию **4VRS Display**.
4. Укажите **Device ID** и **pairing key** с защищённой страницы настройки MQTT именно этого дисплея.
5. Выберите **от 1 до 20 различных сущностей** и сохраните. Их состояния и сведения о помещениях будут передаваться на дисплей.

Для изменения списка откройте **Настройки → Устройства и службы → Интеграции → 4VRS Display** и нажмите **шестерёнку записи интеграции**. Удалять и создавать подключение заново не нужно. Карандаш на странице устройства изменяет его метаданные, а не список выводимых сущностей.

`connected: true` подтверждает соединение с брокером. Если остаётся `has_snapshot: false`, проверьте сопряжение, выбранные сущности и использование одного брокера в HA и на дисплее.

## Фоторамка и анимации

Откройте **Настройки → Мультимедиа → Медиатека**. Загружайте JPEG, PNG, BMP или GIF. Браузер преобразует фото в BMP 240×320 с сохранением пропорций и чёрными полями. GIF передаётся без изменений: **до 240×320 и 256 КиБ на файл**. Для пользовательских медиа нужна FAT32-карта; проверены карты 16 ГБ.

Включите **Слайд-шоу** и отметьте нужные файлы. У каждого своё время показа (1–3600 секунд), у GIF — скорость 25–400%. Настройки сохраняются после перезапуска и OTA. Реальная скорость ограничена SPI 1 МГц: лучше всего работают анимации с небольшими движущимися областями. Выключатель **Показывать телеметрию** позволяет просматривать медиа, продолжая получать MQTT. Без выбранных сущностей HA также доступен медиарежим.

Подключите **отдельный разъём SD** на дисплее: MOSI→23, MISO→19, CLK→18, CS→25. Внутреннего соединения с SPI-разъёмом TFT нет. Прошивка создаёт папки, но не форматирует карту. Медиатека показывает до 64 файлов. Фото хранятся в `/4vrs/photos/`, GIF — в `/4vrs/animations/`. Совпадающие имена не перезаписываются. Встроенный портрет и исходная демка используются как резерв, когда нет пользовательских файлов.

Видео и звук, загрузка медиа из HA, локальные датчики и управление физическими кнопками пока не реализованы. Время показа и слайд-шоу настраиваются из web самого дисплея. Декоративные индикаторы в примерах анимаций не являются живой телеметрией.

## Обновление прошивки

Для OTA используется **образ приложения** `4vrs-display-1.0.0.bin`; factory-образ предназначен для первой установки по UART. ArduinoOTA остаётся доступной в локальной сети, индивидуальный пароль задаётся в **Settings → ArduinoOTA**.

Обновления с GitHub используют подписанный манифест стабильного канала. Перед установкой прошивка проверяет подпись, аппаратный профиль, версию, размер образа и SHA-256. Запись выполняется в неактивный раздел приложения; следующий запуск проверяется, предусмотрен откат при неудачном старте.

Автообновления включены по умолчанию и могут быть заблокированы отдельно для каждого прибора через web или Home Assistant. Любая из блокировок запрещает автоматическую установку. Когда политикой обновлений управляет HA, требуется актуальное разрешение от HA. Новый коммит исходников сам по себе не запускает установку: обновление должно быть опубликовано в подписанном стабильном канале.

- Во время установки прошивки TFT показывает прогресс, затем проверку/перезапуск. При первом переходе со старой версии этот экран станет доступен для последующих обновлений.

```sh
python tools/build.py --config <arduino-cli.yaml> --version 1.0.0
```

Проверки интеграции и выпуска:

```sh
python -m unittest discover -s home_assistant/tests -v
python -m pip install -r tools/requirements-release.txt
python tools/test_release.py
```
